1Define

Carla is paid for the hours she works, and nothing records them. Super admins have no way to see or check her hours.

  • For Carla: a one-click way to start and end a shift, and a page showing her own hours.
  • For super admins: a view of everyone's logged hours, with every edit and its reason.
  • Built per person: turning it on for someone new is a setting, not new code.

Out of scope: pay calculation, invoicing, approvals, and tracking time per task.

Who is involved today: Carla logs time. All super admins can see everyone's hours.

Constraint from the code. Carla will be a support-only admin. Today that role is kept inside /admin/support by middleware.ts, so she couldn't reach the new page, contacts or orders.

Also in scope: the support role's access. Support admins need four areas, and nothing else:

  1. Support (/admin/support). Her first item and where she lands. She has no Dashboard.
  2. Contacts (/admin/contacts and each contact's page)
  3. Orders (/admin/revenue/orders)
  4. My time (/admin/time, but not the super-admin team view)

2Data

New table: company_os.time_entries

One row per shift.

ColumnTypeNotes
iduuidPrimary key
person_iduuid, requiredLinks to people, the person record that outlasts admin access
started_attimestamptz, requiredStored in UTC (universal time)
ended_attimestamptz, empty allowedEmpty means "on shift now"
notetext, optionale.g. "covered weekend inbox"
edited_attimestamptz, optionalSet on any edit, so the log can flag edited shifts
created_at, updated_attimestamptz

Database rules:

  • An end time must come after its start time.
  • A person can have only one open shift at a time. This stops double clock-ins, even from two browser tabs.
  • An index on (person_id, started_at desc) keeps the log page fast.

New table: company_os.time_entry_edits

One row per edit, so edits stack up instead of overwriting each other.

ColumnNotes
id, time_entry_idWhich shift was edited
edited_by_emailCarla or a super admin
old_started_at, old_ended_atThe values before the edit
new_started_at, new_ended_atThe values after the edit
reasonText, required, cannot be blank
created_at

New columns on company_os.admins

  • tracks_time (true/false, default false). Turned on for Carla.
  • time_zone (standard timezone name). Carla's is Asia/Manila, which is UTC+8 with no daylight saving.

Rules

  • Calculated, not stored: shift length, and daily and weekly totals. A break is just two shifts on the same day.
  • Timezones: times are stored in UTC and shown in the person's own timezone. Days and weeks are grouped in that timezone, for Carla and for super admins.
  • Super admins: admins with "can view sensitive" turned on in the database. A new super admin automatically gets the team view and the edit emails.
  • Protection: the database blocks direct browser access. Every read and write goes through a server check, the same pattern as the rest of the system.

3Design: workflows and wireframes

Workflows

A · Carla's daily shift

  1. Sign in. No shift is open, so the start prompt appears.
  2. Start. She taps Start, adjusting the time if she began earlier.
  3. Work. The pill top-right shows elapsed time on every page.
  4. Break (optional). She ends the shift, then starts a new one when she's back.
  5. Finish. She taps End shift, confirms the time and adds a note if she wants.

B · Forgot to end a shift

  1. Sign in. A shift has been open for more than 14 hours.
  2. Blocked. She must set an end time for it before starting a new shift.

C · Carla fixes a time

  1. Pick the entry. She clicks Edit on one of her own shifts from the last 7 days.
  2. Change and explain. She changes the time and writes a reason. Save stays disabled until there's a reason.
  3. Record it. The edit is saved and a row is added to the edit history.
  4. Notify. Each super admin gets an email.

D · A super admin reviews hours

  1. Open the team view. /admin/time/team
  2. Filter. Pick a person and a date range.
  3. Review. Read the totals, and open any "edited" badge to see the history and reasons.
  4. Correct if needed. Super admin edits also need a reason and are logged, but they don't send an email.

Support admin's sidebar

Support admins see this menu, in this order. Signing in, or opening /admin, takes them straight to Support. Any other admin page sends them back to Support. Links on a contact's page that point outside these four areas also bounce back to Support.

5Definition of Done

Definition: what complete means

  • Carla is added as an admin with tracks_time on and time_zone set to Asia/Manila.
  • As Carla, the shift basics work:
    • the start prompt appears and Start creates one row
    • the pill shows elapsed time on every admin page, including /admin/support
    • End fills in the end time
    • a second Start while on shift is refused
  • An end time before its start time is rejected.
  • A shift open for more than 14 hours blocks a new one until it is closed.
  • Her times and day groupings show in Manila time, both for her and for super admins.
  • As Carla, /admin/time works:
    • it shows her shifts with day and week totals
    • she can edit only her own shifts from the last 7 days
  • Edits are recorded and announced:
    • an edit with no reason is refused
    • each edit adds a row to time_entry_edits with the old values, the new values and the reason
    • All super admins each receive the edit email, with the correct old and new times and a working link
  • Support admin access works:
    • the sidebar shows Support, Contacts, Orders and My time, in that order, with no Dashboard
    • signing in or opening /admin lands on Support
    • contacts (the list and each contact's page) and orders open and work, including their actions
    • every other admin page, including /admin/time/team, sends her back to Support
  • /admin/time/team is open to super admins only, and a plain admin is bounced from it.
  • Admins without tracks_time see no pill and no prompt.
